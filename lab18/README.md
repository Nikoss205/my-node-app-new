# Лабораторная работа №18: Исследование методов работы модуля OS

Группа ББМО-01-23. Node.js ≥ 18.3, внешних зависимостей нет (`npm install` не нужен).

| Файл | Задание |
|---|---|
| `os-info.js` | 1. Платформа, тип, архитектура, версия, хост, uptime |
| `os-resources.js` | 2. Процессор, память, средняя загрузка |
| `os-network.js` | 3. Сетевые интерфейсы и пользователь |
| `os-monitor.js` | 4. Мониторинг в реальном времени, `monitor.log` |
| `lib/collectors.js` | Вся работа с модулем `os` (функции принимают `os` параметром — поэтому тестируются на подставной системе) |
| `lib/format.js` | Форматирование: uptime, ГБ, маска MAC, время |
| `tests/lib.test.js` | 26 тестов (`npm test`) |

Какие методы `os` где используются (`lib/collectors.js`): `platform`, `type`, `arch`, `release`, `hostname`, `uptime` — `getSystemInfo`;
`cpus` — `getCpuInfo`, `cpuTotals`; `totalmem`, `freemem` — `getMemoryInfo`; `loadavg` — `getLoadAverage`;
`networkInterfaces` — `getNetworkInfo`; `userInfo`, `homedir` — `getUserInfo`.

## Задание 1

```bash
node os-info.js
```
Скриншот запуска, вывода на вашей ОС и строки с условным выводом («Вы работаете в …»).

## Задание 2

```bash
node os-resources.js                  # процессор, память, средняя загрузка
node os-resources.js --threshold 90   # покажет предупреждение о малом объёме памяти
```
Обычно свободной памяти больше 20%, поэтому для скриншота предупреждения порог повышают параметром `--threshold`
(предупреждение: свободно меньше N%).
На Windows `os.loadavg()` всегда `[0, 0, 0]` — выводится пометка о недоступности.
Если ОС не сообщает частоту (виртуальные машины, Apple Silicon), выводится «недоступна».

## Задание 3

```bash
node os-network.js
```
Список интерфейсов, MAC-адреса замаскированы (`AA:BB:CC:**:**:**`), основной интерфейс — первый внешний IPv4,
данные пользователя и проверка root. На Windows UID/GID отсутствуют (значение −1), поэтому проверка root «не применима».
Чтобы увидеть ветку root на Linux/macOS: `sudo node os-network.js`.

## Задание 4

```bash
node os-monitor.js --snapshot-only                       # только первичный сбор данных (слепок)
node os-monitor.js                                       # слепок -> расчёт CPU -> мониторинг каждые 2 с, Ctrl+C для выхода
node os-monitor.js --stress --cpu-warn 30 --cpu-crit 60  # нагрузка на все ядра, чтобы увидеть ⚠ и ⚠⚠
node os-monitor.js --mem-warn 99                         # предупреждение по памяти
cat monitor.log                                          # Windows: type monitor.log
```
Все параметры: `node os-monitor.js --help` (`--interval`, `--cpu-warn`, `--cpu-crit`, `--mem-warn`, `--log`).

- Загрузка CPU = `busy_diff / total_diff * 100`, где `busy = user + nice + sys + irq`, `total = busy + idle`, разница берётся между двумя замерами `os.cpus()`.
- В терминале обычные строки перерисовываются через `\r`; строки с аномалиями остаются на экране (история).
- Пороги: CPU > 80% — критично (`⚠⚠`), CPU > 50% — предупреждение (`⚠`), свободной памяти < 10% — предупреждение.
- Формат журнала: `[YYYY-MM-DD HH:MM:SS] [ББМО-01-23] Предупреждение: ...`. Файл `monitor.log` создаётся в текущей папке при первой аномалии.
- Ctrl+C выводит «Мониторинг остановлен. Предупреждений: N» и завершает работу с кодом 0.
- `--stress` — только для демонстрации: запускает потоки с бесконечным циклом, останавливаются вместе с программой.
